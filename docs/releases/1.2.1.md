# OpenCleaner 1.2.1

Correctifs de sécurité et de fiabilité issus de l'audit du 26 octobre 2026.

## Sécurité

- **Chemins Win32 ambigus** : refus des chemins UNC, périphériques, volumes, flux alternatifs (ADS), alias 8.3 et composants terminés par un point ou un espace. Un chemin ne peut plus contourner les protections via `//serveur/partage`, `\\?\` ou `PROGRA~1`.
- **Fichiers système** : le répertoire Windows complet est protégé, à l'exception explicite de `Windows\Temp`. `ProgramData` rejoint la liste des racines protégées, et les ruches `UsrClass.dat` sont refusées.
- **Suppression vérifiée** : le chemin résolu par le handle de suppression doit correspondre au chemin validé ; une jonction placée dans un dossier parent ne peut plus détourner la suppression. La sauvegarde est relue et hachée avant chaque suppression.
- **Restauration** : la cible est revalidée, les cibles protégées et le dossier des sauvegardes sont refusés, et le fichier temporaire est haché avant remplacement.
- **Registre** : les clés `Run*`, `Wow6432Node`, `HKU`, `HKCR`, `HKCC`, Defender et les stratégies sont bloquées ; seuls les deux historiques HKCU prévus sont autorisés, et la clé est revérifiée juste avant la suppression.
- **Temporaires** : les dossiers temporaires utilisateur sont résolus via les Known Folders au lieu des variables `TMP`/`TEMP`.
- **Sauvegardes** : contenu chiffré en AES-256-GCM par blocs, métadonnées authentifiées par HMAC-SHA256 et clé protégée par DPAPI. Les anciennes sauvegardes sont migrées au démarrage ; le nouveau format n'est pas lisible par une version antérieure d'OpenCleaner. Perdre la clé locale rend les sauvegardes illisibles ; elles ne sont pas transférables entre utilisateurs ou machines.
- **Journal des transactions** : chaque nettoyage de l'interface et du planificateur est enregistré dans SQLite ; une annulation ou une erreur restaure les suppressions déjà effectuées. Le journal reste distinct des opérations NTFS.

## Fiabilité

- La configuration du planificateur est enregistrée avant la tâche Windows, avec restauration de l'ancienne configuration si l'enregistrement de la tâche échoue.
- Les configurations illisibles ou désynchronisées sont signalées au lieu d'être ignorées silencieusement.
- L'analyseur d'espace disque ne propose plus les lecteurs réseau et non fixés.
- Les tests de sécurité ont été déplacés dans l'arborescence normale du projet ; la CI collecte désormais la couverture.
- Les workflows de release valident les notes de version avant compilation, gèrent les préversions et autorisent la reprise d'une publication existante.
- Le workflow de release peut signer les binaires avec un certificat PFX fourni par les secrets `SIGNING_CERTIFICATE_BASE64` et `SIGNING_CERTIFICATE_PASSWORD` ; sans certificat, les paquets restent non signés.

## Validation

- 90 tests réussis (75 Core, 15 plugins).
- Compilation Release avec `--warnaserror`, aperçu WPF, publication autonome et package Velopack vérifiés.
